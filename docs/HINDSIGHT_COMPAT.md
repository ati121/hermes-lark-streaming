# Hindsight status compatibility

Checked on 2026-11-21 against the official
[Hindsight Hermes integration documentation](https://hindsight.vectorize.io/sdks/integrations/hermes)
and its [1.2.4 source](https://github.com/vectorize-io/hindsight/tree/f14cc1eb5624b0374cb4d82768eb2e0b9c21ae24/hindsight-integrations/hermes).
That integration declares Hermes >= 0.21.4.

## Official behavior

| Feature | Official behavior retained by this plugin |
| --- | --- |
| `recall_indicator` | Defaults to `true`; the provider reports a status only when automatic recall actually injects memory. |
| One recalled fact | `👁️ Hindsight — recalled 1 memory` |
| Multiple recalled facts | `👁️ Hindsight — recalled N memories` |
| Reflect prefetch without a discrete count | `👁️ Hindsight — recalled relevant memory` |
| Disabled indicator, empty recall or failed recall | No indicator is invented. |
| Multiple provider status segments | Preserve the complete status line generated by Hermes, including other providers' segments. |
| `retain_indicator` | Preserve an emitted `👁️ Hindsight — saving to memory…` status; it indicates a queued save, not successful persistence. |
| Retain failure and retry | Leave the integration's logging and retry behavior intact; it does not emit a separate save-success status. |
| Explicit memory tools | Keep `hindsight_retain`, `hindsight_recall` and `hindsight_reflect` tool labels and icons separate from automatic-recall notices. |

The official glyph is U+1F441 U+FE0F. Delivery does not match or rewrite glyphs,
provider names, counts or wording, so a status line with or without a variation
selector remains transparent to the adapter.

`auto_recall`, `recall_sync`, provider-specific filtering, bank selection and
the indicator switches remain the responsibility of the official integration.
With the default `recall_sync=false`, background recall prepares results for a
later turn; a first turn without injected memory need not show a recall icon.
An explicit `hindsight_recall` tool call does not imply that an automatic-recall
indicator should also be generated.

The official provider owns the available retain notification sink. This plugin
preserves status messages emitted by that sink; it does not infer saves from
model output or manufacture a status when upstream supplies no callback.

## Gateway delivery contract

Hermes' dedicated `_send_or_update_status_coro(adapter, chat_id, status_key,
content, metadata)` chooses `adapter.send_or_update_status` when available and
otherwise calls `adapter.send`. Its callback applies upstream notification
policy and scopes the status key to the session and run generation. Hermes uses
the real successful receipt's `message_id` to track progress-message cleanup.

The card plugin wraps this dedicated coroutine with a task-local status marker.
The Feishu send interceptor sees that marker before answer suppression and
passes the status to the original adapter without changing arguments, metadata,
return values or exceptions. The marker is restored after success, failure or
cancellation and is shared across profile plugin copies. It is not an adapter
instance flag and does not exempt a concurrent answer send.

Status messages are not registered as gateway cards, so native edits and deletes
continue to address the original status message. Native adapters keep control of
status-message reuse and any fallback after an edit failure.

## Validation scope

Offline behavior tests exercise the original gateway status contract with the
card interceptors, including existing and not-yet-created cards, indicator and
ordinary-answer separation, receipts, native update/delete paths, failures,
nested scopes, cancellation and concurrent sends across profile plugin copies.
These checks do not make Hindsight service requests or send Feishu messages.

After updating and restarting the gateway, a live check can use a question about
already stored memory with `auto_recall=true` and `recall_indicator=true`.
Observe a turn that actually receives recalled context; the default background
prefetch can require a following turn. The icon's visibility alone does not
establish whether a retain operation has completed.
